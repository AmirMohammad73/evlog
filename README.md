## 📌 درباره پروژه

در محیط‌های سازمانی و فناوری اطلاعات، وقوع اختلال و مشکلات نرم‌افزاری اجتناب‌ناپذیر است. **سامانه ثبت و مدیریت مشکلات نرم‌افزاری** ابزاری تحت وب است که به سازمان‌ها کمک می‌کند سوابق دقیق اختلالات، زمان‌بندی وقوع، علل ریشه‌ای، و عملکرد افراد درگیر را به‌صورت کاملاً متمرکز ثبت و پیگیری کنند.

با استفاده از این سامانه، آشفتگی ناشی از پراکندگی اطلاعات در پیام‌رسان‌ها و فایل‌های مختلف از بین رفته و یک **پایگاه دانش قابل جستجو** از مشکلات و راهکارهای حل آن‌ها ایجاد می‌شود.

## 🎯 هدف پروژه

هنگام از کار افتادن یا بروز اختلال در یک سامانه سازمانی، سوالات کلیدی زیر مطرح می‌شوند:

* ❓ **چه سامانه‌ای** و در چه بخشی دچار مشکل شده است؟
* ⏰ مشکل **چه زمانی شروع شده** و چه زمانی متوجه آن شده‌اند؟
* 👤 **چه کسی** مشکل را گزارش کرده و چه فرد یا تیمی برای رفع آن اقدام کرده است؟
* 🔍 **علت اصلی** مشکل چه بوده و به چه روشی برطرف شده است؟
* 📉 آیا این اختلال باعث **ریزش ترافیک یا کاهش درآمد** شده است؟
* 🔄 آیا این مشکل **سابقه تکرار** داشته است؟

**هدف اصلی این پروژه، پاسخ‌دهی شفاف، دقیق و داده‌محور به سوالات فوق و ایجاد شفافیت کامل در روند رفع اختلالات است.**

## ✨ قابلیت‌های کلیدی

### 🔐 ورود و مدیریت دسترسی‌ها
سامانه دارای کنترل دسترسی بر اساس نقش (RBAC) با دو سطح دسترسی مجزاست:
* 👑 **مدیر سیستم (Admin):** دسترسی کامل به تمامی بخش‌ها شامل مدیریت کاربران، تنظیمات فرم‌ها و مدیریت فیلدها.
* 👔 **کاربر مدیر (Manager):** دسترسی به ثبت، مشاهده، جستجو و خروجی گرفتن از گزارش‌های اختلالات.

### 📝 ثبت گزارش مشکل
* فرم پویا و انطباق‌پذیر جهت ثبت کامل جزئیات اختلال.
* ثبت زمان‌بندی دقیق (آگاهی، شروع و پایان مشکل).
* تعیین نحوه حضور/دسترسی تیم پشتیبانی (حضوری یا ریموت).
* ارزیابی اثرات تجاری (افت ترافیک و ریزش درآمد).

### 📊 تاریخچه و گزارش‌گیری
* 🔍 **جستجوی پیشرفته:** قابلیت جستجو در تمام متون و اطلاعات گزارش‌ها.
* 📅 **فیلترهای زمانی:** امکان محدود کردن گزارش‌ها بر اساس بازه تاریخ.
* 📥 **خروجی Excel:** دانلود فایل اکسل جامع از تمامی گزارش‌ها برای تحلیل‌های ثانویه.
* 📈 **تحلیل اثرات:** مشاهده سریع وضعیت تأثیر اختلال بر ترافیک و درآمد سازمان.

### ⚙️ پنل مدیریت و پیکربندی
مدیر سیستم می‌تواند ساختار فرم ثبت گزارش را به‌صورت پویا تغییر دهد:
* ➕ افزودن فیلد جدید
* ❌ حذف فیلدهای بلااستفاده
* 🔄 تغییر نوع فیلد (متنی، عددی، گزینه‌ای، تاریخ و...)
* 🔒 تعیین اجباری/اختیاری بودن فیلدها
* 📑 مدیریت گزینه‌های فیلدهای انتخابی (Dropdown / Select List)

## 📋 فیلدهای قابل ثبت در گزارش

اطلاعات کلیدی که در هر گزارش اختلال قابل ثبت و پیگیری هستند:

| دسته‌بندی | فیلدهای قابل ثبت |
| :--- | :--- |
| **اطلاعات ساختاری** | اداره کل مسئول • شرکت پیمانکار • نرم‌افزار/سامانه دارای مشکل |
| **زمان‌بندی** | تاریخ و ساعت آگاهی • تاریخ و ساعت شروع • تاریخ و ساعت پایان |
| **عوامل و علل** | نحوه آگاهی از مشکل • علت ایجاد مشکل • نحوه رفع مشکل |
| **ارزیابی انسانی** | فرد مؤثر در حل مشکل • فرد مؤثر در ایجاد مشکل • فرد حاضر یا متصل به صورت ریموت • نوع دسترسی (حضوری / ریموت) |
| **تکرارپذیری** | تعداد دفعات تکرار مشکل • علت تکرار |
| **تأثیرات تجاری** | وجود/عدم وجود ریزش ترافیک • وجود/عدم وجود ریزش درآمد |
